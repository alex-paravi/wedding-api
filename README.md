# Wedding Guest List API

REST API для организаторов свадеб: учёт гостей, рассадка по столам, RSVP-ссылки и статистика. Каждый зарегистрированный пользователь ведёт свою собственную, полностью изолированную от других пользователей свадьбу (multi-tenant модель).

## Стек

- PHP 8.2
- Laravel 12
- MySQL 8.0
- Laravel Sanctum (токен-авторизация)
- Docker / Docker Compose (nginx + PHP-FPM + MySQL)
- Pest / PHPUnit — 18 feature-тестов
- Larastan (PHPStan) + Laravel Pint

## Возможности

- Токен-авторизация через Sanctum
- Управление гостями и столами с полной изоляцией данных между пользователями
- Ролевая модель (`user` / `admin`) — админ видит данные всех пользователей
- Публичные RSVP-ссылки для гостей — подтверждение присутствия без регистрации
- Категории гостей на основе PHP Enum (`friend`, `relative`, `colleague`, `family`)
- Генерация и рассылка приглашений вынесена в очередь — задачи обрабатываются в фоне, по одной на гостя
- Статистика по гостям и столам

## Запуск через Docker

\`\`\`bash
git clone <repo-url>
cd wedding-api
cp .env.example .env

docker-compose up -d
docker exec wedding_api_app composer install
docker exec wedding_api_app php artisan key:generate
docker exec wedding_api_app php artisan migrate
\`\`\`

API станет доступен на \`http://localhost:8080\`.

Чтобы приглашения реально рассылались, нужен воркер очереди:

\`\`\`bash
docker exec wedding_api_app php artisan queue:work
\`\`\`

Без запущенного воркера задачи просто копятся в таблице \`jobs\`, ожидая обработки.

## Тесты

\`\`\`bash
docker exec wedding_api_app php artisan test
\`\`\`

Тесты используют in-memory SQLite (см. \`phpunit.xml\`) и не зависят от MySQL-контейнера.

## Эндпоинты

Все роуты, кроме \`login\` и \`rsvp\`, требуют заголовок \`Authorization: Bearer <token>\`.

### Авторизация

| Метод | Роут           | Описание                       |
| ----- | -------------- | ------------------------------ |
| POST  | \`/api/login\` | Получить токен по email/паролю |
| GET   | \`/api/user\`  | Данные текущего пользователя   |

### Гости

| Метод  | Роут                                 | Описание                                                                      |
| ------ | ------------------------------------ | ----------------------------------------------------------------------------- |
| GET    | \`/api/guests\`                      | Список своих гостей (фильтры: \`?side=\`, \`?status=\`)                       |
| POST   | \`/api/guests\`                      | Создать гостя                                                                 |
| GET    | \`/api/guests/{id}\`                 | Показать гостя                                                                |
| PATCH  | \`/api/guests/{id}\`                 | Обновить гостя                                                                |
| DELETE | \`/api/guests/{id}\`                 | Удалить гостя                                                                 |
| GET    | \`/api/guests/stats\`                | Сводная статистика по гостям и питанию                                        |
| GET    | \`/api/guests/generate-invitations\` | Поставить в очередь рассылку приглашений всем своим гостям (\`202 Accepted\`) |

### Столы

| Метод  | Роут                  | Описание                      |
| ------ | --------------------- | ----------------------------- |
| GET    | \`/api/tables\`       | Список своих столов           |
| POST   | \`/api/tables\`       | Создать стол                  |
| GET    | \`/api/tables/{id}\`  | Показать стол                 |
| PATCH  | \`/api/tables/{id}\`  | Обновить стол                 |
| DELETE | \`/api/tables/{id}\`  | Удалить стол                  |
| GET    | \`/api/tables/stats\` | Статистика по столам и местам |

### RSVP (без авторизации)

| Метод | Роут                              | Описание                                                        |
| ----- | --------------------------------- | --------------------------------------------------------------- |
| POST  | \`/api/invitations/{token}/rsvp\` | Гость подтверждает/отклоняет участие по своей уникальной ссылке |

## Архитектура и решения по безопасности

Проект начинался как учебный, и часть решений — результат целенаправленного поиска и устранения уязвимостей:

- **Авторизация через Policy** (\`GuestPolicy\`, \`TablePolicy\`) отделена от **фильтрации данных** (\`HasOwner\`/\`scopeVisibleTo\`) — Policy решает, разрешено ли действие, scope решает, какие записи вообще показывать.
- **Устранён IDOR** в нескольких местах: прямой доступ к чужим записям через \`id\` в URL, подмена \`user_id\` в теле запроса при создании, подмена \`table_id\` чужого стола при обновлении гостя.
- **Fail-safe проверка роли** — \`isAdmin()\` при отсутствии роли или ошибке возвращает \`false\`, а не \`true\`.
- Категории гостей типизированы через PHP Enum — единый источник истины для валидации, фабрик уведомлений и приглашений.

## Осознанно не реализовано

- **Кэширование статистики** — рассматривалось, но отклонено: корректная инвалидация кэша потребовала бы синхронизировать несколько контроллеров (\`TableController\`, \`GuestController\`), что для текущего масштаба проекта избыточно.
- **\`PdfInvitation\` и \`SmsInvitation\`** — демонстрационные заглушки паттерна Factory, не генерируют и не сохраняют \`invitation_token\` (в отличие от рабочего \`WebInvitation\`).
